# Release checks — plugin `tickr` 0.2.0

Session context: `/tickr:task`, `/tickr:describe`, option `auto_context`. See the [0.1.0 record](plugin-0.1.0.md) for the full checklist.

Date: 2026-11-06. Not released yet.

| Check | Result | Notes |
| --- | --- | --- |
| Lint, typecheck, unit and protocol tests | pass | 355 tests. |
| Dev dependency audit | pass | `npm audit`: no advisory. minimatch is pinned to 11.0.5 through `overrides` (GHSA-g3hv-75wg-m249 affects >= 7.0.0, < 11.0.1; ESLint 10 and typescript-eslint 8 still ask for 10.x). ESLint lints the same 121 files with the same rules. |
| Hook tests (`npm run test:hook`) | pass | 517 tests, on Node 22.17 (Windows), three runs in a row. CI also runs them on Ubuntu and macOS with Node 22, 24 and 26; that run is not recorded here. |
| Bundle equals its source | pass | Two builds are byte-identical. |
| `claude plugin validate --strict` | pass | Claude Code 2.1.318. The extra plugin directory checks (README in the plugin folder, icon) are unchanged from 0.1.x. |
| The session context overrides task and description only for the same project; the link stays computed from `.tickr.json` | pass | Automated tests. |
| Project ids in upper or mixed case in `.tickr.json` | pass | Automated tests: a context set with an upper-case or mixed-case project id applies, the stored task id is in lower case, the mapping hash and link key are those of the file. Real session with an upper-case project id in `.tickr.json`: the hooks recorded the description set by `set-context`, then the one of the file after `clear-context`, then a new one, each change splitting the segment. |
| `/tickr:task` and `/tickr:describe` use the `.tickr.json` of the hooks (`context-info`) | pass | Automated tests: nearest `.tickr.json` below and above the git root, unlinked, changed, invalid or missing file (`{"linked":false}`, nothing of the file printed), upper-case ids printed in lower case, no path, key, hash or session id in the output, nothing written. Real session started two levels below the git root, with `.tickr.json` one level below it: the pre-run `context-info` found that file and the context of this session id; `/tickr:task` called `list_tasks` with its project id (refused with 401, test key) without reading `.tickr.json` nor running `git`; with the file changed after linking, `/tickr:describe` asked to run `/tickr:link` and stopped. |
| `context-info` is pre-authorised, and only it | pass | Pinned by automated tests. Real `claude -p` session without any `--allowedTools`: the pre-run command ran. With `allowed-tools` removed from a copy of the command, Claude Code refused to run the command ("Shell command permission check failed ... requires approval"). |
| An invalid, oversized (over 4 KB) or non-regular context file is ignored | pass | Automated tests. A symbolic link is refused by the same regular-file check (`lstat`); not tested, since creating links on Windows needs extra rights. |
| Two sessions of one checkout have independent contexts | pass | Automated test. |
| A context change splits the segment and the next revisions carry the new task and description | pass | Automated test against a local test server, and a real Claude Code 2.1.318 session: the hooks after `set-context` were recorded with the new description and the session's segment was split at that moment. Nothing was accepted by Tickr in the real session (a test key, refused with 401). |
| `set-context` / `clear-context` validation and atomic write | pass | Automated tests: 11 words, 101 characters, control characters, a task that is not a UUID are refused; `none` sets no task; no temporary file is left behind. |
| Only the confirmed description reaches Tickr as free text | pass | Privacy test: a full session with a context set halfway; every other text value of every request body is an id, a time, a model or a fixed word. |
| SessionStart note for the model | pass | Automated tests (manual, automatic, current context, nothing in unlinked or untracked checkouts). Real session: the model quoted the note word for word. |
| Commands and skill load | pass | Real session: `/tickr:describe` proposed a description and asked for confirmation (manual mode); `/tickr:task` took the project from `context-info`, called `list_tasks` (refused with 401, test key) and stopped without changing anything. Run again after the `context-info` change. |
| `${CLAUDE_SESSION_ID}` in the commands is the session of the hooks | pass | Real session: the command line contained the session id reported by Claude Code, and the context file name was the hash of that id; the hooks of that session applied the context. |
| `set-context` is not pre-authorised | pass | Pinned by an automated test. Real `claude -p` session without a rule: the command was refused (permission denial). |
| Automatic mode with the permission rule runs `set-context` without a prompt | pass | Real `claude -p` session with `auto_context` true and `--allowedTools 'Bash(node --no-warnings *tickr-hook.cjs" set-context *)'`: no question in chat, no permission denial, file written. The rule with the full plugin path also matched. The README recommends only the full-path form: a rule with a wildcard before the script name would also match a script of the same name in a cloned repository. A command chained after it (`&& echo ... > file`) was still refused. |
| The `clear-context` rule | pass | Real `claude -p` session (`/tickr:task clear`): without a rule the command was refused (permission denial); resuming the same session with `--allowedTools 'Bash(node --no-warnings *tickr-hook.cjs" clear-context *)'`, it ran without a prompt and the context file was removed. |
| "Always allow" at the interactive permission prompt | documented, not clicked | Needs an interactive session. Per the Claude Code permissions documentation, "Yes, and don't ask again" saves a prefix rule in the repository's `.claude/settings.local.json` (that repository only); which prefix it saves for these commands was not checked. The README says so and recommends the rules in `~/.claude/settings.json`. |
| Retention removes context files older than 90 days | pass | Automated tests (`pruneContexts` and the flusher's bounds stage). |
